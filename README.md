# 头疼日记 Headache Diary

一个纯静态的偏头痛记录与诱因分析工具。手机、电脑都能打开，无需登录，数据存在本机浏览器。

## 它解决什么问题

只在头痛时记录，几乎什么都会显得可疑。所以要靠「**没头痛的日子**」作对照，才能算出某个因素到底有没有真的把头痛概率推高。

- **每日打卡**：睡眠、压力、咖啡因、饮水、屏幕、酒精、食物、环境与身体状态，末尾勾一下「今天头痛了吗」。约 20 秒。
- **头痛发作**：痛时再记，强度 0–10、部位、性质、伴随症状、先兆、前驱表现、用药与效果。一天可记多条。

不痛 → 只打卡。痛了 → 打卡 + 一条（或多条）发作详情。两者会自动互相关联。

## 分析能力

- **诱因排行**：每个因素对比「有它时的头痛率」与「无它时的头痛率」，给出风险倍数；样本不足的单列，不混进结论
- **延迟查看**：当天 / 前一天 / 前两天（酒精、睡眠这类多为延迟效应）
- **多因素叠加**：同时触发几项与头痛率的对应，看阈值效应
- **用药与反弹性头痛**：按近 30 天用药天数判断药物过度使用风险
- **前驱期提醒**：识别「以为是诱因、其实是发作已开始」的因果混淆
- **你以为的 vs 数据说的**：直觉勾选的诱因与实测倍数的对照
- **日历热力图**、时间分布、数值均值对比
- **导出 CSV**：一天一行，含强度、时长、用药与效果，复诊时给医生看

## 使用

直接用浏览器打开 `index.html` 即可，无需构建、无需后端、无依赖。

数据默认存在本机浏览器（IndexedDB，localStorage 回退），不登录也能完整使用。

## 云端备份

设置页可选登录「云端备份」，登录后：

- 每天的打卡与发作记录会同时写一份到云端（WorkBuddy 云服务的 PostgreSQL）
- 手机和电脑登录同一账号，记录自动合并，按 `updatedAt` 取新（last-write-wins）
- 删除通过墓碑行传播，另一台设备不会把删掉的记录拉回来
- 数据按账号隔离，行级安全（RLS）只允许本人读写自己的行

登录方式：WorkBuddy 账号（一键）或邮箱验证码（免密码）。

未登录时一切照常，只是数据仅在本机；清理浏览器数据会一并清掉，建议定期「导出存档」。

## 每日自动备份

仓库外的自动化任务每天 23:30 把云端全部记录导出为 JSON 快照：

```
backups/headache-YYYY-MM-DD.json   # 当天快照
backups/latest.json                # 始终为最新一份
```

`backups/` 已在 `.gitignore` 中排除——这里面是个人健康数据，不进公开仓库。超过 120 天的快照会自动清理。

## 部署

纯静态，任意静态托管都可以。若用 GitHub Pages：

1. 仓库 `Settings` → `Pages`
2. `Source` 选 `Deploy from a branch`，分支 `main`，目录 `/ (root)`
3. 保存后访问 `https://<用户名>.github.io/Headache-Diary/`

注意：数据按域名隔离。换域名后旧数据不会自动带过来，需用设置页的「导出存档 / 导入存档」迁移。
